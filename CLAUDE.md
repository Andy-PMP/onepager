# One-Pager Generator

Paste messy project notes, get an executive one-pager with RAG status. Portfolio piece for amandapatricks.com. Full brief in [plan.md](plan.md).

**Never commit or push. The user does that.**

## Environment
Windows 11, PowerShell. Python venv at `.venv` (local 3.14; code targets 3.12+).

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
.\.venv\Scripts\python -m pytest
.\.venv\Scripts\ruff check backend

# One real run against Bedrock (costs ~1 cent)
$env:MODEL_ID = "us.anthropic.claude-haiku-4-5-20251001-v1:0"; $env:PYTHONPATH = "backend"
.\.venv\Scripts\python -m onepager.cli samples\dc-migration.txt          # Markdown; add --json for everything
```
LLM grader (`evals/grader.py`, Haiku): only the conditional-risk judgment is scored; it's calibrated on `grader_calibration.json` at the start of every run. Haiku FAILED calibration as a judge of invented links, and small prompt edits flip it either way, so invented links are scored with `invented_connectives` instead. Re-run calibration (`calibrate()`) after ANY grader prompt edit. A stronger grader model would need an IAM change (policy allows only `anthropic.claude-haiku-*`).

Eval (all 17 inputs, ~17 cents + ~4 cents grader, ~1 min; use `--workers 2` to avoid Bedrock throttling): `.\.venv\Scripts\python evals\run_eval.py` → `evals/results/results.md` + `latest.json`. `evals/results/baseline.md` is the first run before prompt tuning (keep for the project page's before/after). Runs at temperature 0 are usually but not always identical run-to-run.

Prompts live in `backend/onepager/prompts/`. Lists come from extraction (Haiku 4.5 garbled multi-array tool calls).

Executive summary design (after two review rounds on the user's WMS notes): the model writes ONE headline sentence (`write.py`, tool `write_headline`); everything after it is built by code from each rule's `RuleResult.summary` clause (`write.facts_paragraph`: red items, amber items, what the notes don't cover, decisions needed). Statuses appear as shape-coded icons, never colour words, in the summary (page strip ✓▲✕?, Markdown ✅⚠️❌❔; the user asked for distinct shapes for colour-blind readers). The headline is validated (figures, `unsupported_attributions`, `invented_connectives`, `headline_style_problems` incl. repeating the facts); correctness problems → visible warning, style problems surviving the one rewrite → headline dropped (facts-only summary). No reporting period anymore: header is always "As of <date>".

Lessons from the user's WMS test (eval case `wms-rollout`): prefer enforcing in code over prompt rules. `ground_facts()` (validate.py) drops extracted dates/budget figures not in the notes; extraction retries once if its text lists contain unsupported figures; `has_estimate()` (rules.py) decides what counts as a change-request estimate; `_drop_duplicate_decisions()` (pipeline.py) removes open decisions that restate an ask. Temperature 0 is *not* fully deterministic since then (1 in 3 runs varied), so check changes with more than one eval run.
